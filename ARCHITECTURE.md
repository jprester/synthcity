# SynthCity Architecture Overview

## Entry Point & Bootstrap

The app starts in `src/main.tsx` which renders `src/App.tsx`. The App wraps everything in a `GameProvider` context and branches on the URL:

- **`?mode=assets`** → `AssetViewerApp` (standalone asset inspector, no game)
- **everything else** → `SynthCityScene` + `UiShell`

---

## Game Initialization Flow

1. **GameContext** (`src/context/GameContext.tsx`) provides global state: settings, refs (`gameRef`, `terminalRef`), and flags like `launchReady`

2. **GameBridge** (`src/scene/systems/GameBridge.tsx`) creates the `Game` instance in a `useEffect`:
   - Passes camera, canvas, settings, controller
   - Sets up environment (fog, lighting)
   - Applies sky background when `launchReady` is true
   - Triggers `onAssetsLoaded` callback when ready

3. **Game class** (`src/classes/Game.js`) constructor initializes:
   - Collision system (BVH-accelerated raycasting)
   - World constants imported from `src/config/world.ts`
   - Environment presets imported from `src/config/environments.ts`

4. **game.init()** is called on user interaction:
   - Creates Player or PlayerCar based on mode
   - Sets `isRunning = true`

## City Modes

Two orthogonal settings control the experience:

- **`mode`** (`"drive"` | `"freeroam"`) — player control scheme
- **`cityMode`** (`"procedural"` | `"finite"`) — world generation method

### Procedural City (`cityMode: "procedural"`)

**GeneratorSystem** (`src/scene/systems/GeneratorSystem.tsx`) streams content around the player using a grid system:

| Generator | Grid Size    | Radius    | Purpose                |
|-----------|--------------|-----------|------------------------|
| CityBlock | 152 (128+24) | 40 blocks | Buildings, decorations |
| Traffic   | 152          | 12 blocks | Flying cars            |
| CityLight | 608 (4× scale)| 8 blocks  | Point lights           |

`GeneratorItem_CityBlock.js` uses Perlin noise to determine building types and places small buildings (2×2 grid), large buildings, towers, and rare mega buildings. **Small building selection (s_01–s_03) is hardcoded here — do not change it.**

### Finite City (`cityMode: "finite"`)

**FiniteCitySystem** (`src/scene/systems/FiniteCitySystem.tsx`) generates a static city once at startup:

- Grid: 15×15 blocks centered on origin (configurable)
- Layout is generated by `generateLayout()` or loaded from a JSON file via `?layout=`
- Sub-systems: `FiniteCityGround`, `FiniteCityCollision`, `FiniteCityBoundary`
- Boundary walls (invisible collision planes) prevent the player from leaving the grid

## Building Registry (`src/config/buildingRegistry.ts`)

Single source of truth for all building model definitions. Asset loading, emissive configuration, model manifest entries, instanced mesh keys, and ad model keys are all **auto-derived** — no other files need updating when adding buildings.

### Series

| Series | Keys | Placement | Notes |
|--------|------|-----------|-------|
| `SMALL_SERIES` | s_01, s_02, s_03 | 2×2 sub-grid per block | Selection hardcoded in `GeneratorItem_CityBlock.js` |
| `LARGE_SERIES` | s_04_xx | One per block, noise-selected | Used in both procedural and finite modes |
| `TOWER_SERIES` | s_05_xx | One per block, rare | Used in both procedural and finite modes |
| `SLIM_TOWER_SERIES` | s_06_xx | 2×2 sub-grid, downtown only | Finite city mode only; replaces s_01–s_03 in downtown |
| `LANDMARK_SERIES` | landmark_xx | One instance per type per city | Finite city only; guaranteed placement in downtown |

### Asset Pipeline

- **OBJ models**: share external texture materials (`building_01` – `building_10`)
- **GLB models**: use embedded PBR materials stored as `__embedded_{modelKey}`
- `mergeGLTFMeshes()` in AssetManager recombines multi-material GLB mesh groups into a single geometry with material groups, allowing `InstancedMesh` with `Material[]`

## District System (`src/config/cityLayouts/districts.ts`)

Overlays named rectangular zones on the finite city's block grid. Each district biases the Perlin noise thresholds that decide whether a block generates as empty, small, large, or tower.

| District | Empty | Small | Tower | Character |
|----------|-------|-------|-------|-----------|
| `default` | 0.10 | 0.80 | 0.975 | Balanced |
| `downtown` | 0.00 | 0.30 | 0.850 | Dense, towers, landmarks |
| `industrial` | 0.10 | 0.60 | 0.999 | Mid-size, no towers |
| `residential` | 0.10 | 0.95 | 0.999 | Mostly small |
| `outskirts` | 0.30 | 0.85 | 0.999 | Sparse |

`getDistrictBias(gi, gj, districts)` returns the bias for a block. First match wins.

In the downtown district, the small-building slot uses `SLIM_TOWER_SERIES` instead of s_01–s_03. Landmarks are placed via a pre-pass before the main grid loop, always landing in downtown.

---

## JSON Layout System

`FiniteCityLayout` is a fully serializable type (plain numbers and strings). Layouts can be:

- **Generated** deterministically from a seed via `generateLayout(seed, gridSize, districts)`
- **Exported** to JSON via `exportLayoutToJSON(layout)` (`src/config/cityLayouts/export.ts`)
- **Loaded** at runtime via `loadLayoutFromURL(url)` (`src/config/cityLayouts/import.ts`) using `fetch()` from `public/layouts/`

## Player System

### PlayerCar (Drive Mode)

`src/classes/PlayerCar.js`:
- Autopilot: car bobs sinusoidally, player looks around
- Manual: mouse controls pitch/roll
- Collision via `game.collider.intersectsSphere()`
- Crash freezes for 2s, then respawns

### Player (Freeroam Mode)

`src/classes/Player.js`:
- WASD movement, R/F for altitude
- Smooth quaternion-based camera look

### Controller

`src/controllers/usePlayerController.ts`:
- Captures keyboard/mouse during pointer lock
- Tracks ~20 input states

### Pointer Lock

`src/scene/systems/PointerLockSystem.tsx`:
- Source of truth is `document.pointerLockElement`
- Controller and blocker state derived from actual lock state

## Scene Structure

### Procedural city

```
<Canvas>
  <FrameLimiter />
  <GameBridge />           → Environment, lighting, post-processing
  <GeneratorSystem />      → City blocks, traffic, lights
  <PlayerSystem />         → Player car visuals
  <AudioSystem />          → Audio management
  <PointerLockSystem />    → Input capture
</Canvas>
```

### Finite city

```
<Canvas>
  ...
  <FiniteCitySystem />     → Ground, instanced buildings, collision, walls
  ...
</Canvas>
```

### Asset viewer

```
<Canvas>
  <RendererSetup />
  <AssetLoader />          → Reuses Game.load() for asset pipeline
  <OrbitControls />
  <SceneContent />         → Single or gallery view of all registered models
</Canvas>
```

## Asset Loading

**AssetManager** (`src/assets/AssetManager.ts`):
- Manifest-based loading (textures, models, materials)
- Supports OBJ, GLB
- Lazy material creation with factories
- Methods: `getModel()`, `getMaterial()`, `getTexture()`

### Loading Flow

1. `game.load()` → creates AssetManager
2. Progress shown in terminal
3. `onAssetsLoaded()` sets `launchReady = true`

---

## Visual Presets (`src/scene/effects/VisualPresets.ts`)

Post-processing effect configuration. Identified by kebab-case ID.

| ID | Name |
|----|------|
| `default` | Default |
| `intense-neon` | Intense Neon |
| `blade-runner` | Blade Runner |
| `retro-crt` | Retro CRT |
| `hypercolor` | Hypercolor |

Each preset controls: bloom, chromatic aberration, vignette, color grading, scanlines, noise, and per-category emissive intensity multipliers (ads, buildings, neons, ambient, smoke).

| Param | Values | Notes |
|-------|--------|-------|

| `sfx` | `0`, `1` | |

## Data Flow Summary

```
URL params
  → querySettings.ts (parse + merge onto defaults)
    → GameSettings
      → cityMode = finite?
          → FiniteCitySystem
              → generateLayout() or loadLayoutFromURL()
                  → district pre-pass (landmark placement)
                  → per-block noise + district bias
              → InstancedBuildings / InstancedMegaBuildings
      → cityMode = procedural?
          → GeneratorSystem
              → GeneratorItem_CityBlock (Perlin noise, streaming)

Input (Controller)
  → PlayerSystem (useFrame priority 1)
    → Game.updatePlayer() → position/collision
      → GeneratorSystem (useFrame priority 2) → spawn/despawn
        → Visual Components → render meshes
          → Post-processing (EnhancedEffects)
```
